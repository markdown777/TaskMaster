# Edge 3.5.0 Upgrade Design

**日期**: 2026-06-08
**时间**: 北京时间
**项目**: TaskMaster Edge Extension
**目标目录**: `edge-version/`
**当前基线**:
- Chrome 主目录版本: 3.5.0
- Edge 目录版本: 3.0.0

## 1. 背景

当前仓库根目录为 Chrome 浏览器插件版本，已经升级到 3.5.0，并包含 AI 智能录入、适配器分层、API Key 加密、搜索交互优化和界面升级等能力。

`edge-version/` 目录仍然停留在 3.0.0，并且已经作为 Edge 商店版本提交过。现在需要将 Edge 版本升级到 3.5.0，同时保持它仍然适用于 Microsoft Edge Add-ons 商店上架。

## 2. 目标

本次升级的核心目标如下：

1. 将 Chrome 3.5.0 的核心功能同步到 `edge-version/`。
2. 保留 Edge 版本当前已有的平台差异配置，尤其是多语言和商店上架相关字段。
3. 在修改前先进行整目录备份，确保可以随时回退到 Edge 3.0.0。
4. 将 Edge 目录中的文档、更新说明和截图素材一起升级到 3.5.0 语义。
5. 最终产出一个可继续测试、打包并提交 Edge 商店的 3.5.0 目录。

## 3. 非目标

以下内容不在本次设计范围内：

- 不修改数据库结构，也不执行任何清库操作。
- 不额外引入 Chrome 3.5.0 之外的新功能。
- 不删除 Edge 的多语言能力。
- 不直接在商店后台代为提交，仅准备好本地目录和配套材料。

## 4. 已确认约束

- 采用方案 A: 以 Chrome 3.5.0 为功能源，将功能同步到 Edge 版。
- 继续保留 Edge 商店需要的多语言配置。
- 代码和文档一起升级。
- 截图素材一起处理。
- 修改前必须先做整目录备份。

## 5. 设计原则

### 5.1 功能对齐优先

业务逻辑、界面、AI 能力、适配器、加密能力尽量与 Chrome 3.5.0 保持一致，降低后续双端维护成本。

### 5.2 平台差异保留

不把 Edge 版做成与 Chrome 版完全相同的目录副本，而是保留所有与 Edge 商店上架直接相关的字段、目录和文档结构。

### 5.3 先备份再修改

任何同步和覆盖动作都以目录备份为前提。备份完成前，不对 `edge-version/` 做正式写入。

### 5.4 分层迁移

本次升级不是单纯改版本号，而是按以下层次处理：

1. 目录备份
2. 核心代码同步
3. Edge 特定配置回补
4. 文档和素材升级
5. 校验和验收

## 6. 升级方案

采用“整包覆盖同步，最后回补 Edge 专属配置”的方案。

### 6.1 方案说明

1. 先备份当前 `edge-version/` 目录，保留原始 3.0.0 版本。
2. 将 Chrome 3.5.0 的核心代码和新增目录同步到 `edge-version/`。
3. 对不能直接覆盖的 Edge 特有文件执行差异修复或回补。
4. 再同步 Edge 商店所需文档、更新说明和截图素材描述。
5. 最后做版本、结构和静态校验。

### 6.2 选择原因

- 相比逐文件手工迁移，覆盖同步更不容易漏掉 `services/`、`adapters/` 等 3.5.0 新结构。
- 相比重建一个新的 Edge 目录，本方案对现有 `edge-version/` 干扰更小，更适合在当前仓库内增量升级。
- 通过“覆盖后回补”可以同时满足功能一致性和 Edge 商店兼容性。

## 7. 文件同步边界

### 7.1 直接同步的内容

Chrome 3.5.0 中与核心功能相关的文件和目录会同步到 `edge-version/`，包括但不限于：

- `popup.html`
- `popup.css`
- `popup.js`
- `options.html`
- `options.js`
- `background.js`
- `taskManager.js`
- `shareManager.js`
- `utils.js`
- `constants.js`
- `services/`
- `adapters/`
- 图标和必要静态资源

这些文件代表 3.5.0 的主要能力，例如：

- AI 自然语言录入
- 图片输入或视觉识别能力
- 存储、网络、加密适配器
- 搜索交互和 UI 升级
- API Key 安全管理

### 7.2 需要保留或回补的 Edge 差异

以下内容不能被机械覆盖，而应在同步后保留或回补：

- `edge-version/manifest.json` 中的多语言字段
- `default_locale`
- `minimum_edge_version`
- 作者、主页等 Edge 商店信息
- `edge-version/_locales/`
- Edge 商店专用文档
- `Screenshot/` 目录及其上架素材组织方式

### 7.3 不做粗暴覆盖的内容

以下内容不采用“直接拿 Chrome 文件整份替换”的方式：

- `manifest.json`
- `_locales/`
- Edge 提交说明和上架文档
- 与商店截图说明绑定的素材引用关系

## 8. Manifest 设计

### 8.1 升级方式

以 `edge-version/manifest.json` 为基础做增量升级，不直接用根目录的 Chrome `manifest.json` 完整替换。

### 8.2 必须保留的字段

- `name: "__MSG_extName__"`
- `description: "__MSG_extDesc__"`
- `default_locale`
- `minimum_edge_version`
- 作者字段
- 主页字段

### 8.3 必须修改的字段

- 版本号从 `3.0.0` 升级为 `3.5.0`
- 图标、入口、脚本路径与升级后的目录保持一致
- 如 Chrome 3.5.0 引入了必要的新脚本引用，则一并同步

### 8.4 权限策略

如果 Chrome 3.5.0 没有新增权限，则 Edge 版保持现有权限集合不扩张。

如果 Chrome 3.5.0 功能依赖新增权限，则仅在确有必要时同步到 Edge 清单中，并确保不添加无关权限，减少审核风险。

## 9. 多语言设计

### 9.1 保留多语言结构

继续保留：

- `edge-version/_locales/en/messages.json`
- `edge-version/_locales/zh_CN/messages.json`

### 9.2 文案升级原则

- 扩展名称和简介继续通过 `__MSG_*__` 管理
- 多语言短描述保持适合商店展示和审核阅读
- 详细功能亮点写入 README、更新说明和提交文档，不在 manifest 简介中堆叠过长内容

### 9.3 需要同步的语义

文案要体现 3.5.0 的能力升级，例如：

- AI 智能任务录入
- 安全的 API Key 配置与加密
- 交互和界面优化
- 搜索和归档体验升级

## 10. 文档与商店素材设计

### 10.1 需要升级的文档

以下 Edge 文档需要一起升级到 3.5.0 语义：

- `edge-version/README-EDGE.md`
- `edge-version/README.md`
- `edge-version/EDGE-VERSION-SUMMARY.md`
- `edge-version/EDGE-STORE-SUBMISSION-GUIDE.md`
- 更新说明文档

### 10.2 文档升级目标

旧文档目前仍围绕 3.0.0 的基础任务管理功能展开，需要更新为 3.5.0 版本的定位和能力说明，重点体现：

- AI 自然语言录入
- 图片输入或识别
- API Key 管理和本地加密
- UI 与交互升级
- Edge 商店提交时推荐使用的新功能亮点

### 10.3 截图素材策略

`edge-version/Screenshot/` 目录纳入升级范围。

处理方式如下：

1. 检查当前截图是否仍为 3.0.0 界面和功能。
2. 更新文档中对截图的引用和说明，避免仍引用旧版本语义。
3. 代码升级完成后，确认哪些截图必须重新生成，哪些截图可以继续复用。

本次设计的目标不是立即生成所有新截图，而是把截图升级工作纳入交付范围并与 3.5.0 文档对齐。

## 11. 实施步骤

### 11.1 备份阶段

1. 复制整个 `edge-version/` 目录，生成一个独立备份目录。
2. 备份目录命名应清晰标识为 Edge 3.0.0 备份，便于回退。
3. 备份完成后再开始任何正式同步动作。

### 11.2 同步阶段

1. 先对比根目录与 `edge-version/` 的文件结构。
2. 同步 Chrome 3.5.0 的核心代码文件和新增目录。
3. 确保 `services/`、`adapters/`、静态资源和脚本引用一并到位。

### 11.3 Edge 修复阶段

1. 修正 `manifest.json`，保留 Edge 多语言和平台字段。
2. 修正 `_locales/` 文案。
3. 检查 HTML 中脚本引用路径、图标路径和资源路径。
4. 修正 Edge 文档和上架说明。

### 11.4 校验阶段

1. 统一检查版本号。
2. 检查关键文件是否缺失。
3. 检查语法错误和明显路径错误。
4. 检查文档与功能描述是否一致。

## 12. 验证策略

### 12.1 结构验证

确认 Edge 目录中以下关键内容存在且路径正确：

- `manifest.json`
- `popup.html`
- `popup.css`
- `popup.js`
- `options.html`
- `options.js`
- `background.js`
- `services/`
- `adapters/`
- `icons/`
- `_locales/`

### 12.2 版本验证

确认以下区域全部升级到 3.5.0：

- Manifest 版本号
- README 和版本说明
- 提交文档中的版本描述

### 12.3 功能验收重点

- 弹窗页面可正常打开
- 任务创建和列表展示不受影响
- 设置页可打开，3.5.0 配置项能正常显示
- 后台脚本正常加载
- Edge 多语言配置未丢失
- 文档和素材说明与实际功能一致

### 12.4 静态校验

在实施完成后，对近期修改文件执行诊断检查，重点关注：

- 语法错误
- 未引用文件
- 路径大小写问题
- 明显 API 使用错误

## 13. 回滚策略

如果出现以下问题，可按层级回滚：

### 13.1 全量回滚

如果升级过程中出现大面积异常，直接恢复到备份目录中的 Edge 3.0.0 版本。

### 13.2 局部回滚

如果问题局限在以下范围，可只回退对应文件：

- `manifest.json`
- `_locales/`
- 某个业务脚本
- 某个文档文件

### 13.3 回滚原则

- 不删除备份目录
- 不执行破坏性重置
- 保留所有中间修改记录，便于对比问题来源

## 14. 成功标准

当满足以下条件时，本次设计视为达成：

1. `edge-version/` 的功能层面对齐 Chrome 3.5.0。
2. Edge 商店需要的清单字段、多语言和平台信息仍然可用。
3. 版本号统一升级到 3.5.0。
4. Edge 文档、更新说明和截图素材说明同步到 3.5.0。
5. 得到一个可继续测试、打包并提交到 Edge 商店的目录。

## 15. 风险与注意事项

- 直接覆盖可能冲掉 Edge 商店特有字段，因此 Manifest 和 `_locales/` 必须单独处理。
- 3.5.0 的新增目录如果遗漏同步，会导致运行时报错或页面脚本加载失败。
- 文档和截图如果不同时升级，会造成商店展示和实际功能不一致。
- macOS 环境需要特别注意文件路径大小写和资源引用一致性。
