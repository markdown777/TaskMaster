# Edge 插件 WordPress 隐私政策页面设计

**日期**: 2026-06-08
**时间**: 北京时间
**项目**: TaskMaster Edge Extension
**目标用途**: 生成一个可直接复制到 WordPress 单独页面中的隐私政策正文，主要服务于 Microsoft Edge 插件商店审核

## 1. 背景

TaskMaster Edge 3.5.0 已完成本地打包和商店资料整理，当前需要补充一个可公开访问的隐私政策页面 URL，用于填写 Microsoft Edge Add-ons 商店的隐私政策字段，并为审核人员提供与插件真实行为一致的隐私说明。

用户希望：

- 生成一份可直接复制到 WordPress 的单独页面内容
- 内容以通过 Edge 浏览器插件审核为主要目标
- 页面采用标准完整版隐私政策结构
- 页面内容必须与插件当前真实行为一致

## 2. 目标

本次设计目标如下：

1. 输出一份适合发布在 WordPress 页面中的完整隐私政策正文
2. 文案优先满足 Edge 插件审核口径
3. 内容与 TaskMaster Edge 3.5.0 的实际数据处理行为一致
4. 页面结构清晰，用户可直接复制到 WordPress 使用

## 3. 非目标

以下内容不在本次设计范围内：

- 不生成 WordPress 主题代码或页面模板
- 不自动发布到 WordPress 后台
- 不撰写站点级通用法律条款，只聚焦当前插件场景
- 不替代正式法律顾问意见

## 4. 已确认约束

- 采用“完整版隐私政策”形式
- 输出为可直接粘贴的 WordPress 页面正文
- 写作重点是提升 Edge 审核通过率
- 文案必须克制、准确、避免夸大或模糊表述

## 5. 插件真实行为基线

隐私政策必须与以下真实行为保持一致：

- 插件默认将任务数据和大部分设置保存在本地浏览器环境
- Edge 跨设备同步默认关闭，只有用户手动开启后才会同步部分数据
- AI 功能只有在用户主动配置并主动使用时才会调用第三方 AI 服务
- 用户输入的文本或图片内容可能在 AI 功能使用时发送到用户自行配置的第三方 AI 服务
- 扩展本身不加载远程 JS 或 Wasm，不使用远程代码执行
- 扩展不包含广告跟踪、遥测或分析脚本
- `downloads` 权限仅在用户主动导出备份时使用

## 6. 内容策略

### 6.1 主体口径

页面主基调采用“默认本地处理、用户主动触发、最小必要说明”：

- 不把插件描述成默认云端服务
- 不把所有行为都表述为开发者主动收集
- 明确区分“本地存储”“可选同步”“用户主动使用 AI”

### 6.2 审核导向写法

页面需要清晰覆盖审核敏感点：

- 收集哪些信息
- 这些信息如何使用
- 数据是否上传
- 是否存在第三方处理
- 是否存在远程代码
- 是否存在广告、分析、跟踪
- 用户有哪些控制权

### 6.3 风险规避

文案要避免以下风险：

- 避免写“完全不接触任何数据”这类绝对化表述
- 避免写“所有数据都会上传云端”这类与实际不符的内容
- 避免遗漏 AI 第三方服务说明
- 避免遗漏同步默认关闭这一关键事实

## 7. 页面结构设计

最终页面建议采用以下结构：

1. 页面标题：隐私政策
2. 生效日期说明
3. 适用范围
4. 我们处理的信息类型
5. 信息的使用方式
6. 本地存储与 Edge 同步说明
7. AI 功能与第三方服务说明
8. 数据导出与下载说明
9. 远程代码与跟踪说明
10. 数据安全说明
11. 用户选择与控制权
12. 儿童隐私
13. 政策更新
14. 联系方式

## 8. 重点章节设计

### 8.1 信息类型

说明插件可能处理以下用户主动输入或配置的信息：

- 任务标题
- 备注
- 标签
- 时间与提醒配置
- AI 提供商配置
- 用户主动输入的文本或图片内容

### 8.2 本地存储与同步

这一部分需要强调：

- 默认本地存储
- 同步默认关闭
- 只有用户手动开启后，部分数据才会通过 Edge 浏览器同步能力同步到用户账号环境

### 8.3 AI 与第三方服务

这一部分是审核重点，必须明确：

- AI 功能是可选功能
- 只有用户主动配置并主动使用时才会触发数据发送
- 发送目标是用户自行配置的第三方 AI 服务
- 开发者不为用户统一提供 AI 账号

### 8.4 下载与导出

明确写出：

- 下载权限仅用于用户主动导出任务备份
- 不执行静默下载

### 8.5 远程代码与跟踪

明确写出：

- 不加载远程代码
- 不使用广告跟踪、遥测或分析脚本

## 9. 输出格式设计

最终输出采用适合 WordPress 粘贴的正文格式：

- 一级标题
- 二级标题
- 段落
- 短列表

不输出复杂 HTML，不依赖特定主题样式，确保：

- 在 WordPress 区块编辑器中易于粘贴
- 在经典编辑器中也易于整理
- 审核人员阅读时结构清楚

## 10. 语言风格

文案风格要求如下：

- 正式
- 克制
- 清晰
- 去 AI 味
- 尽量避免法律腔过重但信息不足的问题

## 11. 成功标准

当满足以下条件时，本设计视为达成：

1. 可直接复制到 WordPress 单独页面
2. 可作为 Edge 商店隐私政策 URL 指向页面
3. 与插件真实行为一致
4. 对审核人员足够清楚，能够降低因隐私披露不清导致的审核风险

## 12. 后续入口

本规格确认后，下一步直接生成最终隐私政策正文，不需要额外实现代码。
